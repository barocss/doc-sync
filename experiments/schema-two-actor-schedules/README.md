# Bounded two-actor schema schedules (issue #6, partial)

From the workspace root, using Node 22.19.0 or newer:

```sh
npm run build
node --test experiments/schema-two-actor-schedules/test.mjs
```

This independent experiment imports only published package entry points. It does
not import the original local runtime-document-schema-contract experiment or any
unpublished native API. No network or browser is used.

## Achieved contract

Four deterministic renamed schemas (seeds 0, 1, 7, 65535), each with two complete
rounds: A and B insert on separate stored text blocks before delivery, selected
uplink/downlink order drains FIFO queues, and each actor undoes its own insertion
in both orders. Explicit scalar attributes remain intact. Expected models are
small literals, not generated by the CRDT or applyEdits. Server and peer models,
pending queues, undo eligibility, and observer errors are checked.

The public observer API can emit fallback events. On fallback the mirror reloads
the public model as required by that API; otherwise applyEdits applies the event.
This is not an independent oracle for fallback event correctness. The separate
literal expected model check still runs at each settled checkpoint.

Additional targeted two-actor tests cover a same-block foreign insertion surviving
A's undo, peer move and delete invalidating a caller-owned stamp guard, and a late
invalid sync Client.edit batch leaving model/snapshot/history/pending/events
unchanged. The stamp guard is application-side code; these tests do NOT claim the
raw path edit API intrinsically provides strict-ID targeting. Structural tests
assert remote convergence and unchanged state after rejected guarded dispatch.

## Replay and reduction

`generate(seed)`, `serialize(fixture)`, `deserialize(json)`, and `replay(fixture)`
provide deterministic replay. Format 1 stores the schema and ordered causal
round descriptors with a SHA-256 checksum. Initial x/y text, command expansion,
and checkpoint expected models are defined by this version of schedules.mjs;
this is not a self-contained arbitrary command trace. Keep this code version
alongside a reproducer. SHA-256 detects accidental corruption, not authentication.

`reduce(fixture)` removes only whole rounds, never half an edit/delivery/undo
lifecycle. Every candidate is schema- and schedule-validated before replay, and
only the same failure class is retained. Oracle, convergence, event-mirror,
pending, history, and execution failures are distinguished. The reducer is greedy
round deletion, not a general schema/command minimizer. Its unit test explicitly
injects a round-dependent oracle failure; no real engine bug is claimed. A success
is not reduced into an artificial failure. The two-actor targeted checks are not
yet represented as reducer inputs.

## Remaining scope (keep #6 open)

Generated structural/group/grid schedules, actual attribute/mark mutations,
arbitrary command and schema shrinking, same-position conflicting inserts,
reducer integration for targeted stale/batch cases, and native/browser execution
remain unimplemented. Mark names are generated descriptors, not exercised mark
operations. No long-running load, GC, reconnect, durability or recovery claim.

## Validation

Node 22.19.0: 11 tests passed, 0 failed. Earlier failures were fixture setup and
public API contract mistakes (transport presence method, synthetic initial
paragraph, protected-history disposal, fallback observer semantics, move endpoint)
and were corrected without changing the engine. No engine defect found.
